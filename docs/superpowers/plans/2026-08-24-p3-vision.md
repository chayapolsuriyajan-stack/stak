# P3: Vision (images + light video) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The read tool returns images (and sampled video frames) as model-visible image blocks; all three providers translate them natively; transcripts stay lean by persisting paths, never base64.

**Architecture:** New `ImageBlock` in the internal content-block union. `ToolResult.images` flows through the loop into the same user message as its `tool_result`. Adapters map: Anthropic native blocks, OpenAI `image_url` data URIs, Ollama `images[]`. Persistence strips payloads (`stripImagePayloads`) and resume refills them from disk (`rehydrateImages`). Video frames come from ffmpeg into OS temp.

**Tech Stack:** No new dependencies; ffmpeg is an optional external binary with graceful degradation.

## Global Constraints

- No new runtime npm dependencies. Node >= 20 ESM `.js` suffixes.
- Image whitelist: png jpg jpeg webp gif — verified by extension AND magic bytes. Cap 5 MB/file.
- Video extensions: mp4 webm mov mkv. Max 8 frames (arg `maxFrames` 1–8), JPEG in `os.tmpdir()`, never the project dir.
- Missing ffmpeg → clear error result, not a crash. Unknown-capability models attempt and surface the provider error (spec wording).

### Task 1: Types + persistence stripping

**Files:** Modify `src/agent/types.ts`, `src/tools/types.ts`, `src/sessions/store.ts`; Create `src/agent/images.ts` (+ `images.test.ts`).

```ts
// src/agent/types.ts additions
export type ImageMediaType = "image/png" | "image/jpeg" | "image/gif" | "image/webp";
export interface ImageData { mediaType: ImageMediaType; data: string; sourcePath: string }
export interface ImageBlock extends ImageData { type: "image" }
// ContentBlock union += ImageBlock
```
`src/agent/images.ts`: `sniffImageMediaType(buf: Buffer): ImageMediaType | undefined` (png `\x89PNG`, jpeg `\xFF\xD8\xFF`, gif `GIF8`, webp `RIFF…WEBP`), `IMAGE_EXTENSIONS`, `isImageFile(path)`, `isVideoFile(path)`, `stripImagePayloads(message): Message` (data → ""), `rehydrateImages(history: Message[], readFile?): Promise<Message[]>` (refill empty-data blocks from disk; unreadable → replaced by a `[missing image: path]` text block).

Store.append persists `stripImagePayloads(message)`.

### Task 2: read tool images + video frames

**Files:** Modify `src/tools/read.ts`, `src/tools/types.ts` (ToolResult += `images?: ImageData[]`); Create `src/tools/video.ts` (+ tests).

`video.ts`: `extractVideoFrames(videoPath, maxFrames, run): Promise<{ frames: Buffer[]; note: string }>` where `run(cmd)` is an injectable spawn helper returning `{stdout, stderr, exitCode}` and reading produced files — default impl shells to ffmpeg/ffprobe. Duration via ffprobe; seek-percentage extraction; fallback `fps` filter when ffprobe is missing (note says frames came from the file start).

Read flow: directory/text paths unchanged; image ext → sniff → size cap → `{ output: "[image …]", images: [...] }`; video ext → extract → multiple JPEG images + note listing timestamps; sniff failure → "file content doesn't match its extension" error.

### Task 3: Loop threading + provider adapters + TUI metadata

**Files:** Modify `src/agent/loop.ts`, `src/providers/{anthropic,openai,ollama}.ts` (+ their tests), `src/tui/hooks/useAgentSession.ts`.

Loop: after each tool_result push sibling ImageBlocks into `resultBlocks`; extend `tool-call-result` event with `images?: { mediaType; sourcePath }[]` (no pixels).
Adapters: Anthropic `{type:"image", source:{type:"base64",…}}`; OpenAI user messages become content arrays with `image_url` data URIs (tool-role messages stay text-only — sibling images ride the next user message there); Ollama `images[]` attached to the first message emitted from the same internal message. Ollama pre-flight: if history has images and reported capabilities exist and lack `"vision"` → error event naming the limitation.
TUI: `tool-call-result` appends one `[image path]` notice per returned image.
