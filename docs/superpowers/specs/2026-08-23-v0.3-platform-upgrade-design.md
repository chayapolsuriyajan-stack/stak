# Stak v0.3 — Platform Upgrade Design

Date: 2026-08-23
Status: Approved (design walkthrough 2026-08-23)

## Summary

Upgrade stak from a chat-loop-with-file-tools into a small platform, closing the
largest gaps with opencode and Claude Code:

1. **Modes**: replace the four permission modes (`plan | ask | accept-edits |
   auto-bypass`) with three (`plan | build | auto`).
2. **Hooks**: a declarative JSON `beforeTool` / `afterTool` hook system.
3. **Tools**: a `todo` list tool and a keyless `webfetch` tool.
4. **Vision**: file-based image reading and light video frame sampling.
5. **Output**: opencode-style per-tool render cards plus markdown rendering of
   completed assistant replies.

Approach chosen: hook-first core refactor, then thin features on top
(Approach 1). No new runtime dependencies. Five independently shippable phases,
each leaving `npm test && npm run typecheck` green.

## 1. Modes: `plan | build | auto`

`PermissionMode = "plan" | "build" | "auto"` in `src/config/types.ts`.

| mode    | read-only tools | edit/write tools | bash & MCP tools |
|---------|-----------------|------------------|------------------|
| `plan`  | allowed         | denied outright  | denied outright  |
| `build` | allowed         | runs silently    | prompts          |
| `auto`  | allowed         | runs silently    | runs silently    |

- `RiskTier` (`read-only | edit | bash`) is unchanged; it is exactly the
  vocabulary the table needs. MCP-sourced tools keep their always-gated tier.
- `MODE_CYCLE` becomes `["plan", "build", "auto"]` for shift+tab cycling;
  `MODE_LABELS` rewritten accordingly.
- `ask`, `accept-edits`, and `auto-bypass` are removed. Migration on load:
  `ask → build`, `accept-edits → build`, `auto-bypass → auto`, each producing a
  one-time warning surfaced through the existing config warnings channel.
- Headless `-p`: default remains deny-everything-gated when no prompter exists.
  `--permission-mode` accepts only the new trio. In headless `build`, edits run
  but bash is still denied (no prompter to ask). The old
  `--permission-mode auto-bypass` value errors with a hint toward `auto`.
- System prompt: mode-specific paragraph injected as today; plan wording stays,
  build/auto get accurate descriptions of their gating.

## 2. Hooks: declarative JSON

New module `src/hooks/` (`HookRunner`). Configuration in either
`~/.stak/config.json` or `.stak/settings.json` — project entries win over
global ones of the same hook name, matching mcpServers precedence.

```jsonc
{
  "hooks": {
    "beforeTool": [
      { "name": "block-force-push", "match": "bash", "run": "node scripts/check.js" }
    ],
    "afterTool": [
      { "name": "fmt", "match": "edit|write", "run": "prettier --write $FILE", "timeout": 10000 }
    ]
  }
}
```

- Two hook points only: **`beforeTool`** and **`afterTool`**.
- `match` is a regex tested against the tool name; absent means match-all.
- Hook command receives JSON on stdin: `{ tool, args, cwd, phase }`.
  `$NAME`-style env vars are expanded from top-level string args (e.g. `$FILE`,
  `$PATH`, `$COMMAND`) plus `${VAR}` environment expansion, same mechanism as
  MCP server config.
- **Veto semantics**: a nonzero exit from a `beforeTool` hook blocks the tool
  call; stderr becomes the denial reason returned to the model. `afterTool`
  failures never fail the tool call; their stderr is logged as a dim transcript
  notice.
- Default `timeout` 10s unless overridden per hook; a timed-out `beforeTool`
  hook blocks the call with an explanatory reason.
- **Execution order**: permission check first, then beforeTool hooks, then
  execute, then afterTool hooks. Denied calls never trigger hooks.
- `/hooks` built-in command lists loaded hooks with source file and phase.
- Secrets rule unchanged: `.stak/settings.json` must not hold literals; use
  `${VAR}` expansion.

### Integration point

The loop's tool execution path (`executeTool` wiring in the session layer)
wraps calls as: `permission.check() → hooks.beforeTool() → tool.execute() →
hooks.afterTool()`. HookRunner is constructed at startup from merged config and
passed alongside the PermissionManager.

## 3. New tools

### todo

- Single tool: `todo_write({ todos: [{ content, status: "pending" |
  "in_progress" | "completed" }] })` — full-list replacement each call.
- State file `.stak/todo.json`; created on first write.
- `/todo` command prints the current checklist; `/clear` resets it.
- `riskTier: "read-only"` deliberately: it writes stak's own bookkeeping file,
  not project files, so plan mode can draft a todo list while researching.
- System prompt gains one paragraph instructing use for multi-step tasks and
  keeping exactly one task `in_progress`.

### webfetch

- Args: `{ url, maxChars? }`. Defaults: ~20k char output cap, 5 MB download
  cap, 30s timeout, only `text/html` and `text/*` content types accepted.
- HTML reduction without dependencies: drop `<script>`, `<style>`, comments;
  strip remaining tags; keep links inline as `[text](href)`; collapse
  whitespace.
- `riskTier: "read-only"` — usable in plan mode.
- No search tool in this release; the system prompt notes that webfetch needs a
  concrete URL.

## 4. Vision (file-based)

- New content block: `{ type: "image", mediaType, data (base64), sourcePath }`.
  `ContentBlock` union extended; `ToolResult` gains `images?: ImageData[]`.
- **read** on image extensions (`png jpg jpeg webp gif`) returns an image block
  instead of text. Guards: extension whitelist AND magic-byte sniff; 5 MB cap
  per file with a clear error otherwise.
- **Video (light)**: extensions (`mp4 webm mov mkv`) cause read to sample up to
  8 evenly spaced frames via ffmpeg into OS temp as JPEGs, returned as images
  annotated with timestamps; `maxFrames` arg overrides the count. ffmpeg
  missing → clean error result suggesting installation. Temp frames are never
  written inside the project directory.
- **Provider mapping**:
  - Anthropic: native image blocks nested in the `tool_result` content array.
  - OpenAI: images forwarded as `image_url` parts of the user message that
    carries the following turn's context.
  - Ollama: base64 entries in the message's `images[]` field.
- Ollama models reporting no vision capability (via `modelInfo().capabilities`)
  get a friendly pre-flight denial naming the limitation rather than a raw
  server error; unknown capability → attempt and surface provider error.
- **Sessions**: JSONL stores `sourcePath`, never base64. On resume, images are
  re-read from disk if present, else rendered `[missing: path]`.
- **Rendering**: TUI transcript shows an `[image path]` card. Headless
  `json`/`stream-json` emit metadata only; `--include-images` opts base64 back
  into `json` output for scripting.

## 5. Output format

### Tool cards

New `src/tui/renderers.ts`: map from tool name to card renderer, generic
fallback for MCP tools.

```
✻ Read src/agent/loop.ts (lines 1–249)
✻ Edit src/tools/todo.ts
     + const todos = load()
     − const TODO = "old"
     … 14 more changed lines
✻ Bash $ npm test   ✓ exit 0
✻ Grep "PermissionMode" → 7 matches
☑ 3/7 done · ◐ wire HookRunner · ☐ webfetch tool
✻ mcp github.list_issues (12 results)
```

- edit/write cards render a genuine colored diff (reuse existing edit-string
  computation), capped near 12 changed lines with an overflow hint.
- bash shows the command and exit status; grep/glob show query and match count;
  read shows path (+ line range when partial); webfetch shows host + URL;
  todo renders the checklist glyph state.
- Long outputs collapse behind the existing `firstLines` pattern, tuned per
  renderer.

### Markdown replies

- Small built-in renderer (no dependency): headings, bold/italic, inline code,
  fenced code blocks (indented block, dimmed gutter), `- ` and ordered lists.
- Applied only to completed assistant messages printed into Ink `Static`
  scrollback; the live streaming tail remains plain text so the existing
  flicker fix and Static model are untouched. On completion the tail is
  replaced by the formatted version — the same single swap that happens today,
  never duplicated output.

### Mode UI

Status bar and shift+tab cycle show `plan → build → auto`; permission prompts
relabel; `/permissions [mode]` validates against the new trio and hints on old
names.

## 6. Testing & rollout

Five phases, each shippable alone, each leaving the suite green:

| Phase | Delivers | Test focus |
|-------|----------|------------|
| P1 | plan/build/auto modes + HookRunner + migration | manager decisions per mode/tier, old-mode mapping, hook veto/timeout/regex-match/stdin payload |
| P2 | todo + webfetch tools | schema validation, todo file round-trip, HTML stripping fixtures, caps and timeout |
| P3 | vision end-to-end | magic-byte sniff, size caps, ffmpeg sampling fallback, per-provider translation, JSONL path persistence |
| P4 | tool cards + markdown renderer | renderer selection, diff truncation, markdown parser cases |
| P5 | README/config docs rewrite, version 0.3.0 | — |

Breaking changes (documented in README at P5): permission-mode values renamed
(`ask → build`, `auto-bypass → auto`, `accept-edits` folded into `build`);
everything else additive. `-p` semantics unchanged from v0.2.

## Out of scope (explicitly)

Web search, clipboard image paste, JS plugin modules, subagents, LSP/formatter
integration, checkpoints, granular per-rule permissions, sandboxed bash.
